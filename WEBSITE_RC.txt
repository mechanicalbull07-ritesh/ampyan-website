AMPYAN Website V1 local release candidate

Compatibility: backend df045fc46b89d0a56819c67d4279821a1f6f8466.
Flutter reference: 0400688e0d9420e5a3c59d56eaa7587624a56227.
Application source and templates are frozen at validated P4A hashes.
The complete validated files retain existing Diagnosis, News and analytics work.
No production/staging changes, migration, push or deployment is authorized.

Runtime: CPython 3.14.3. Install requirements-test.txt in a fresh environment.
Pillow is pinned to 12.1.1, the version actually used during P4A validation;
this corrects stale packaging, not the validated runtime behavior. The existing
google-auth 2.49.0.dev0 pin is retained and its wheel availability was verified.
All production dependencies and test dependency closure are pinned.

Clean checkout validation (backend checkout must be clean at the exact RC):
python tools/validate_website_rc.py --root <NEW-/tmp-directory> \
  --backend <frozen-backend-checkout> \
  --backend-python <separate-backend-test-environment-python> \
  --postgres-bin <PostgreSQL-18-bin-directory>

Install the backend environment from its own requirements-test.txt; do not mix
its dependency pins with the website environment. The runner uses only explicit
local synthetic databases, ignores inherited database URLs, disables PostgreSQL
TCP, verifies the actual data directory, and stops/removes its cluster afterward.
No recovery directory, Codex log, pre-existing database or sibling Flutter tree
is needed. The repository-local Diagnosis JSON is immutable synthetic contract
input copied byte-for-byte from the frozen Flutter commit, not user data.

Required deployment variable names: DATABASE_URL, SECRET_KEY,
AMPYAN_API_BASE_URL, ENV (production), PORT (provided by host).
Google login additionally requires GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET
with an OAuth audience accepted by the backend. Credentials remain external.
Other optional environment names are inventoried in the external RC manifest.
.env.example contains only intended public configuration defaults/placeholders.
Never version databases, real credentials, tokens, signing material, cache/build
outputs, audit/recovery reports or runtime-generated synthetic records.

The historical analytics local validation tool remains source-controlled as
test infrastructure; no generated database or synthetic account dump is included.
Service-record deletion is not exposed by this website RC. Vehicle deletion is
validated against P4B; Add Service and service history use the frozen API.
Do not broaden the RC by introducing a separate service-record deletion feature.

Live Google OAuth and interactive browser/physical-device smoke remain release
execution checks; local automated validation does not represent a deployment.
