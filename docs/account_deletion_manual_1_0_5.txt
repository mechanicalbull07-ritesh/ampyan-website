ADMIN OWNERSHIP REVIEW
1. Use an authorized, active administrator's authenticated Backend/Garage session.
2. Open /admin/account-deletion; open a request's ownership review.
3. Require the server-created authenticated request and unchanged registered email

4. Find the original inbound support thread from that registered mailbox. Inspect
   the actual sender and mail authentication/anti-spoofing headers; a display name,
   quoted/forwarded sender, arbitrary supplied address or screenshot is not proof.
   Where authenticity cannot be established, keep NOT VERIFIED and investigate.
5. Store a restricted review record linking the thread to the request and noting
   successful sender authenticity review. Do not copy secrets into the record.
6. Enter the actual sender email and SHA-256 of that review record, confirm receipt,

   its registered email; it does not trust the supplied user ID. The administrator

7. If either proof is absent, stop. Do not approve or execute deletion. The owner
   cannot approve their own deletion as an administrator; use an admin handoff.

EXECUTION AND COMPLETENESS
Execute verified deletion calls the existing P16C service. It fences mutations,
blocks the account, performs child-first relational erasure/anonymization, checks
for remaining owner data, and clears the worker private cache. Cross-owner content
and approved anonymous discussion topology are preserved. No SQL row surgery.
PROCESSING is not COMPLETED. Failed execution records an error, never completion;
retain approved provenance for an authorized retry of the same request.
Review every media/provider/public-content/local-cleanup task. Record real work
and restricted evidence; a hash alone does not demonstrate cleanup. Verify every
worker's private cache and applicable Firebase/AI/provider attributable stores.

COMPLETION

administrator choose Complete. The backend durably commits COMPLETED and clears
owner linkage/receipt recovery. It does not create or send a completion email.
